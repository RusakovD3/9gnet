# Валидация Купмана по внешней телеметрии

Этот файл описывает только проверку внешнего временного ряда. Формулы Хаусдорфа,
Купмана и Ляпунова, а также границы их интерпретации, собраны в
[math_and_attacks_ru.md](math_and_attacks_ru.md).

Этот контур переводит GNet9 от синтетической демонстрации к воспроизводимому пилоту. Он работает только локально с CSV и не посылает сетевые пакеты, команды маршрутизаторам или правила ACL.

## Контракт входного CSV

Файл UTF-8 (допускается UTF-8 BOM) обязан содержать строго возрастающие `timestamp_seconds` и следующие поля:

| Поле | Тип | Значение |
|---|---|---|
| `timestamp_seconds` | число | Время отсчёта в секундах от начала выгрузки. Значения строго возрастают. |
| `risk_score` | число 0…1 | `forecast_risk_score` той же ревизии модели Купмана; это не вероятность атаки. |
| `attack_onset` | 0/1 или true/false | Подтверждённое начало инцидента, полученное после расследования SOC/NOC. |
| `attack_id` | строка, необязательно | Стабильный идентификатор подтверждённого инцидента. |
| `attack_kind` | строка, необязательно | Класс инцидента: например, `dos`, `ddos`, `syn_flood`, `power`. |

В выгрузку не следует включать payload пакетов, логины, IMSI, номера телефонов, полные IP-адреса абонентов или иные персональные данные. Для контроля происхождения отчёт сохраняет SHA-256 исходного файла, но не копирует его строки.

## Запуск

```powershell
python main.py --validate-telemetry-csv data/koopman_telemetry.csv
```

Получится `output/telemetry_validation_report.json`. По умолчанию ранние 70% временного ряда используются для выбора порога, а поздние 30% — для независимой проверки. Параметры допуска можно явно менять:

```powershell
python main.py --validate-telemetry-csv data/koopman_telemetry.csv `
  --telemetry-training-fraction 0.70 `
  --telemetry-min-events-per-partition 5 `
  --telemetry-min-precision 0.90 `
  --telemetry-min-recall 0.90 `
  --telemetry-max-false-warnings-per-hour 0.10
```

Порог выбирается без обращения к независимой проверочной части ряда (`holdout`).
Предупреждение засчитывается, только если оно находится за 10–20 секунд до
подтверждённого начала атаки. Несвязанные с такими началами эпизоды считаются
ложными. Это предотвращает подмену проверки подгонкой по будущим меткам.

## Применение и границы ответственности

Если и ранняя часть, и независимая проверочная часть (`holdout`) выполнили
критерии, отчёт получает статус `PASSED_FOR_SUPERVISED_PILOT`. Только такой
файл можно передать в симулятор:

```powershell
python main.py --attack-scenario predictive-demo `
  --calibration-report output/telemetry_validation_report.json `
  --show-window
```

Профиль меняет лишь порог раннего предупреждения в модели. Он не означает, что `risk_score` стал вероятностью и не включает автоматическое изменение реальной сети. Для промышленного внедрения необходимы согласованные runbook, ручное утверждение ремаппинга, отдельный контур управления оборудованием с RBAC/MFA и журналом аудита, мониторинг дрейфа и повторная валидация на новых периодах. Ни один прогнозный метод не способен честно обещать 100% точность для атак без наблюдаемых предвестников.
